## เฟส 1 — แชทร้านค้า (ปรับจากของเดิม)

state ของบทสนทนา (server เป็นคนตัดสินทุกตัวเลข client แค่แสดงผล):

| state | บอทพูด/แสดง | ปุ่ม |
|---|---|---|
| `welcome` | แพ็กวันนี้ + สิทธิ์คงเหลือ (1 แพ็ก/วัน กทม.) | เลือกแพ็ก 29 / 59 / 99 |
| `age_gate` | ครั้งแรกเท่านั้น: ยืนยันอายุ 20+ | ยืนยัน / ยกเลิก |
| `quote` | **Bubble card การชำระเงิน** (ดูหัวข้อถัดไป) | คัดลอกเลขบัญชี / คัดลอกยอด / ส่งสลิป / ยกเลิกออเดอร์ |
| `slip_check` | กำลังอ่าน QR บนสลิป | — |
| `done` | เติม 58 Energy แล้ว + เลขออเดอร์ | กลับเกม |
| `error` | ข้อความไทยต่อ error code (`slip_unreadable`, สลิปซ้ำ, หมดเวลา, ยอดไม่ตรง) | ลองใหม่ / ติดต่อแอดมิน |

งานที่ต้องทำ:
1. เปิดแชทใหม่แล้วกลับไป state ของออเดอร์ที่ค้างอยู่ (`GET /api/shop` คืน open order อยู่แล้ว)
2. ตาราง error code → ข้อความไทย ไว้ที่เดียว ห้ามโชว์ code ดิบ
3. ปุ่ม "ติดต่อแอดมิน" แนบเลขออเดอร์ (ไปช่องทางที่เจ้าของกำหนด เช่น LINE OA) สำหรับกรณีโอนผิดยอด/อยากขอคืนเงิน
4. ประวัติการซื้อในแชท (เลขออเดอร์ วันที่ แพ็ก สถานะ) — ไม่ต้องออกใบให้ผู้เล่นรายคน เพราะใช้ใบสรุปรายวัน (หัวข้อเฟส 3) ถ้าผู้เล่นขอหลักฐานให้ใช้เลขออเดอร์อ้างอิง
5. เทส: ทุก state transition + การกดซ้ำ (`requestId` idempotent) + ข้ามวันเที่ยงคืน กทม.
6. **ผลจากการเลิกใช้ QR:** แอปธนาคารไม่รับยอดจากการ์ดอัตโนมัติ ผู้เล่นต้องวาง/พิมพ์ยอดในแอปธนาคารเอง จึงมีโอกาสโอน 29.00 แทน 29.64 มากขึ้น
   - ปุ่มคัดลอกยอดแบบมีทศนิยมครบ และแสดงยอดตัวใหญ่ที่สุดในการ์ด
   - ตรวจสลิป: ใช้ mini QR บนสลิปเหมือนเดิม (เป็น QR ของธนาคารบนสลิป ไม่เกี่ยวกับ QR รับเงินที่ยกเลิก) — ยอด/บัญชีปลายทางยืนยันจาก statement
   - ยอดที่โอนผิด (ไม่มีเศษ/เศษไม่ตรง) จะตกไปที่ "เงินเข้าที่ไม่ตรงรายการ" ให้แอดมินผูกด้วย `POST /api/admin/orders/:id/credit`
   - ลบ `promptpay.mjs` ออกจากเส้นทางจ่ายเงิน (เก็บ `crc16` ไว้ เพราะ `slipqr.mjs` ใช้)

### Bubble card การชำระเงิน (ตัดสินแล้ว 2569-11-08)

การ์ดในแชท 1 ใบต่อ 1 ออเดอร์ สร้างจากข้อมูลฝั่ง server ทั้งหมด ผู้เล่น**ไม่ต้องพิมพ์หรือยืนยันยอดในแชท**:

```
┌──────────────────────────────────────┐
│ ⚡ แพ็ก 29 บาท · 58 Energy             │
│ ยอดที่ต้องโอน                          │
│        ฿29.64            [คัดลอกยอด]  │
│ ⚠ โอนให้ตรงทุกสตางค์                   │
│ ธนาคารกสิกรไทย                         │
│ 177-1-50013-3           [คัดลอกเลข]  │
│ บจก. แมช มูฟ อัลฟ่า                     │
│ ออเดอร์ #A1B2C3 · หมดเวลา 29:41        │
│ [ ส่งสลิป ]          [ ยกเลิก ]       │
└──────────────────────────────────────┘
```

กติกา:
- การ์ดแสดงค่าจาก `GET /api/shop` (open order) เท่านั้น — client ห้ามคำนวณหรือแก้ยอด/เลขบัญชี
- "คัดลอกยอด" คัดลอก `29.64` (ไม่มี ฿ / คอมมา) "คัดลอกเลข" คัดลอก `1771500133` (ตัวเลขล้วน วางในแอปธนาคารได้ทันที)
- **การตรวจ = เทียบกับข้อมูลในการ์ด (ออเดอร์ฝั่ง server)** ไม่ใช่ตัวเลขที่ผู้เล่นพิมพ์:
  1. สลิป: อ่าน mini QR → `trans_ref` ไม่ซ้ำ + CRC ถูก → เติมทันที (เหมือนเดิม)
  2. statement: เงินเข้า **ตรงยอดในการ์ดทุกสตางค์** + อยู่ในช่วงเวลาของออเดอร์ → ยืนยัน
  3. ยอดไม่ตรงการ์ด → "เงินเข้าที่ไม่ตรงรายการ" ให้แอดมินผูกเอง
- สถานะการ์ดอัปเดตในที่เดิม: รอโอน → กำลังตรวจสลิป → เติมแล้ว ✓ / หมดเวลา / ยกเลิก (ไม่สร้างการ์ดใหม่ซ้ำ)
- เปิดแชทใหม่ระหว่างมีออเดอร์ค้าง → แสดงการ์ดเดิมพร้อมเวลาที่เหลือ

## เฟส 4 — ส่งต่อให้ฝ่ายบัญชี

**รายวัน (แอดมิน ~5 นาที ทุกเช้า):** อัปโหลด statement ของเมื่อวาน → เคลียร์ "ส่งสลิปแต่ไม่พบเงิน" / "เงินเข้าไม่ตรงรายการ" → ปิดวัน (ระบบไม่ยอมปิดถ้ายังมีรายการค้าง)

**รายเดือน (ภายในวันที่ 5 ของเดือนถัดไป** เพื่อให้บัญชีมีเวลายื่น ภ.พ.30 ภายในวันที่ 15 หรือวันที่ 23 ถ้ายื่นออนไลน์):

| ไฟล์ | เนื้อหา |
|---|---|
| `daily_YYYYMM.txt` | สรุปรายวันทุกวันของเดือนตามรูปแบบที่ฝ่ายบัญชีขอ (วันที่ + 3 แถว + ก่อน VAT / VAT / รวม) — ไม่มีหัวบริษัท/เลขที่ ฝ่ายบัญชีออกใบกำกับภาษีเอง |
| `summary_YYYYMM.csv` | 1 แถว/วัน: วันที่, ชิ้น+ยอดต่อแพ็ก, ก่อน VAT, VAT, รวม + แถวรวมเดือน |
| `reconcile_YYYYMM.csv` | ต่อวัน: ยอดใบ vs เงินเข้า statement, หางทศนิยม, รายการค้าง |
| `credit_notes_YYYYMM.pdf` | ใบลดหนี้ (ถ้ามี) |

ledger รายออเดอร์เก็บฝั่งเรา ส่งให้เมื่อบัญชีหรือสรรพากรขอเท่านั้น
ช่องทางส่ง: แอดมินดาวน์โหลดจากหน้าแอดมินแล้วส่งเอง ระบบไม่ส่งอีเมล/LINE ออกไปเองจนกว่าเจ้าของจะอนุมัติ
